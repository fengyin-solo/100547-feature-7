# 山地地质灾害隐患巡查与治理工作台

面向隐患点建档、坡体形变与裂缝观测、雨量预警发布、避险搬迁与治理工程验收的山区地质灾害防治工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `geohazard-patrol:entries` 这一项，或调用 `resetModule(模块)`。

## 边坡观测规则（slope 模块）

- **任务分派**：监测方式字典只在 `frontend/src/data/monitoring.ts` 定义一次，页面下拉和
  任务分派逻辑读的是同一套。人工观测测点按片区分给本片区观测人，自动监测测点归监测组；
  已停测的测点不再派任务。
- **权限**：片区观测人只能维护本片区的人工观测测点，自动监测测点只有监测组能改，
  本片区之外的记录一律只读。测点编号是身份字段，任何人不得改动；监测方式只有监测组能调整，
  越权改动一律拦下并说明原因。
- **状态流转**：待观测 → 正常 → 变形加剧 → 已停测，单向、按固定次序，不能跳步或回退
  （`modules.ts` 里 slope 的 `actionSources` 登记了每个动作的源状态）。
- **重复提交**：同一测点编号只登记一次；同一测点同一观测日的结论重复提交时，
  以先登记的那条为准，后续提交忽略。
- **结论联动**：观测结论提交成功后，削坡减载清单自动多一条待复核测点
  （工序编号 `REVIEW-<测点编号>`，同一测点只补一条），复核确认后进入正常工序流转。
- **越界挡回**：本期位移绝对值超过 ±50mm 的登记、编辑、结论提交一律挡回。
- **冲突判定**：一次提交踩中多条规则时按优先级判定——越权拦截 > 越界挡回 > 重复登记 > 流转校验，
  只报最先命中的那条。
- 规则链的冒烟验证：`cd frontend && npm run smoke`（esbuild 打包后在 Node 里跑，不依赖浏览器）。
